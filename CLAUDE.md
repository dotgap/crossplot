# crossplot

Coordinated, cross-filtered charts for TypeScript: a modern take on dc.js. Brush one chart and every
linked chart re-aggregates. The library owns the cross-filter engine and the filter store; drawing is
handed to pluggable renderers. Published to npm as 0.x; breaking changes go in minor versions with a changeset.

## Layout

pnpm workspace (`packages/*`, `examples/*`), TypeScript ESM, Node >= 20.

| Path | What it is |
| --- | --- |
| `packages/core` | `@crossplot/core`. Headless engine, filter store, dashboard model. **Zero runtime deps.** |
| `packages/core/src/engine/crossindex.ts` | `CrossIndex`: columnar bitmask cross-filter engine (the hot path). |
| `packages/core/src/engine/{local,worker,protocol}.ts` | Same engine on the main thread or behind a Web Worker message protocol. |
| `packages/core/src/binning.ts` | Compiles dimension specs (linear, log, calendar, category, top-N, grid) to per-row bin ids. |
| `packages/core/src/dashboard.ts` | `createDashboard`: wires data, engine, filters and charts; coalesces updates per frame. |
| `packages/core/src/filters.ts` | `FilterStore`: plain, observable, serializable filter state. |
| `packages/core/src/specs.ts` | Spec builders: `bin`, `category`, `top`, `count`, `sum`, `mean`. |
| `packages/core/src/renderer.ts` | The renderer contract (`Renderer`, `RenderHandle`, `Datum`, `Intent`). |
| `packages/core/src/dom/` | `@crossplot/core/dom`: optional plain-DOM `countDisplay` and `dataTable`. Only place core touches the DOM. |
| `packages/plot` | `@crossplot/plot`: Observable Plot renderer (peer dep `@observablehq/plot`). One file, `src/index.ts`. |
| `packages/react` | `@crossplot/react`: React hooks and `<Chart>` (peer dep `react` >= 18). Tests are `.tsx` with testing-library. |
| `packages/vue` | `@crossplot/vue`: the same API as Vue composables (shallow refs) and `<Chart>` (peer dep `vue` >= 3.3). One file, `src/index.ts`. |
| `packages/svelte` | `@crossplot/svelte`: the same API as Svelte 5 runes in `src/runes.svelte.ts` (shipped uncompiled as `.svelte.js`, compiled by the app) plus a `chart` action. Vitest compiles runes and test components with `vite-plugin-svelte`. |
| `examples/dinosaurs` | Editorial Vite demo on Paleobiology Database dinosaur finds (21,253 rows, `public/dinosaurs.json`). |
| `packages/core/src/engine/sort.ts` | Per-bin value sort behind exact incremental edges and tiles. |
| `docs` | VitePress docs site: guide, live examples (`docs/examples/*.ts`), API reference generated by TypeDoc into `docs/api/` (gitignored). |
| `.github/workflows/docs.yml` | Builds the docs with the demo under `/demo/` and deploys to GitHub Pages (manual, or on push once the `DOCS_DEPLOY` variable is `true`). |
| `.changeset/`, `.github/workflows/release.yml` | Changesets release setup: all `@crossplot/*` packages share one version; the workflow opens a version PR and publishes to npm by trusted publishing (OIDC, no token), gated on the `RELEASE_ENABLED` variable. Actions are pinned by SHA and checked by zizmor in CI; pnpm waits 3 days before installing new releases (`minimumReleaseAge`) and runs no install scripts. |
| `scripts/check-packages.mjs` | `pnpm check:packages`: npm metadata, README/LICENSE and publint checks for every public package (CI). |
| `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `LAUNCH.md` | Contributor docs; `LAUNCH.md` lists the manual steps left before going public. |
| `bench/engine.mjs` | Engine-only brush latency (start and drag percentiles) on seeded synthetic data; runs against `packages/core/dist`. CI runs it at 1M and 10M rows as a non-blocking job. |

## Commands

```sh
pnpm install
pnpm build        # tsc -b for the packages (the demo and bench use dist/)
pnpm test         # vitest; tests import package sources through aliases in vitest.config.ts
pnpm typecheck    # packages + demo
pnpm demo         # builds packages, then starts the Vite dev server for the demo
pnpm docs         # builds packages and the API reference, then starts the docs dev server
pnpm bench [rows] # engine brush latencies, default 1M rows (`pnpm bench 1e6,1e7` for both)
pnpm check:packages # after a build: package.json metadata and publint for every public package
pnpm changeset    # add a changeset (needed for user-facing changes to packages/*)
pnpm --filter dinosaurs build    # production build of the demo, also run in CI
pnpm --filter docs build         # production build of the docs site, also run in CI
```

Lint and formatting commands live in the root `package.json` scripts and CI in
`.github/workflows/ci.yml`; check there for the current set before sending a change. CI must pass.

Run one test file with `pnpm vitest run packages/core/test/crossindex.test.ts`, or one test with `-t "<name>"`.

## Design principles

- **Core has zero runtime dependencies** and is headless. Never add a `dependencies` entry to
  `packages/core/package.json`, and never touch `document`/`window` outside `src/dom/`. Renderers and
  framework wrappers are separate opt-in packages with peer dependencies (TanStack style).
- **Data flows one way.** Renderers get `ChartData` plus the chart's own filter and report `Intent`s
  (`brush`, `brushXY`, `select`, `reset`) in data space. They never read or write filters directly.
- **Crossfilter semantics.** Each chart aggregates rows that pass every filter except its own.
- **Everything across the engine boundary is serializable** (specs, filters, results), because the
  engine runs in a worker by default. Specs are plain objects; `view` goes to the renderer untouched.
- **Filters are exact on raw values**, not snapped to bins. Ranges are half-open `[lo, hi)`.
- **Performance is a feature.** The engine is typed arrays, a bitmask of one bit per dimension
  (max 32 dimensions), and incremental updates that only touch rows whose bit flips. A drag on one
  binned dimension of a large table is answered from prefix-sum tiles instead, and a slow box drag
  on a grid (or two brushes moved in turn) from 2-D summed-area tiles, built a slice at a time
  across frames and idle time (`CrossIndex` doc comment). Avoid per-row allocations and closures
  in the hot path; check `pnpm bench` before and after engine changes.
- **Maps are aggregated:** `lngLat()` bins coordinates into a world grid and the Plot `map` mark draws
  one dot per cell on a plate carrée frame, so a brushed box is an exact lng/lat filter. Basemaps
  come from the app (the demo ships Natural Earth and GPlates coastlines), never from a package.
- **Deferred, out of scope for now:** live or streaming data, accessibility work, other map
  projections and per-row points, DuckDB/Mosaic backends. Don't build toward them unless asked.

## Conventions

- Strict TypeScript (`noUncheckedIndexedAccess`, `verbatimModuleSyntax`: use `import type`), ESM with `.js` extensions in relative imports, no default exports.
- Public API is whatever `packages/*/src/index.ts` exports; keep JSDoc on exported types and options.
- Engine changes need a test, and the brute-force reference test in
  `packages/core/test/crossindex.test.ts` must keep passing (and cover any new spec or filter kind).
- Renderer tests run in jsdom (`// @vitest-environment jsdom`) with `engine: "local"` and a microtask
  `schedule`, then `await dash.idle()`.
- Keep the README package table and example, and the docs guide pages, in sync with API changes.
- Commits and pull requests: Conventional-style imperative titles (`feat(plot): add a box plot mark`),
  squash-merged; PR descriptions state what the change adds. User-facing changes to `packages/*` add a
  changeset (`pnpm changeset`). New packages copy the publish metadata, README and LICENSE from
  `packages/plot` (`pnpm check:packages` enforces it).

## Skills

Task guides live in `.claude/skills/`:

- `add-chart-type`: add a mark to the Plot renderer, or a new renderer or dimension kind.
- `run-demo`: build, serve and smoke-test the dinosaur demo in a headless browser.
- `engine-tests`: write engine and dashboard tests, including the brute-force reference check.
